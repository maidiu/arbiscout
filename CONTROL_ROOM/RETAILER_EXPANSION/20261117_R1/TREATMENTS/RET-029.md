## 2026-11-17 LEGO capture and fixture validation

- **Capture:** one local read-only HTTP GET of `https://www.lego.com/en-us/categories/sales-and-deals`; LEGO robots.txt allowed the path. Raw HTML stayed local: 1,174,608 bytes, SHA-256 `9c1726178de633da4453a47c244f615e672aef469b6f3078f8ce2e2ad15c174b`.
- **Mechanism:** the page exposes a JSON-LD ItemList and `__NEXT_DATA__` Apollo state with 18 `SingleVariantProduct` and `ProductVariant` objects. No private API, sign-in, pagination or product-page crawl was used.
- **Extraction:** `ProductVariant.price` is current; `listPrice` is retained as a reference only when greater. All 18 captured sets had both; `salePercentage`, set number, variant SKU and availability are retained.
- **Identity:** LEGO set number (`productCode`) is the exact set identity; variant SKU is separate. GTIN is not captured.
- **Implementation:** `ENGINEERING/arbiscout_app/providers.py` (`lego_products_from_html`, `fetch_lego_deals`) plus `--source lego` and `--snapshot`. Control room and catalog include LEGO.
- **Tests:** synthetic `__NEXT_DATA__` fixture covers paired prices, centAmount fallback, current-only rows, set/variant identity and missing payload. Local real capture produced 18 rows; local catalog test produced 18 LEGO rows.
- **Status:** FIXTURE_VALIDATED, not LIVE_VALIDATED. LEGO terms/permission, pagination completeness, retention and independent review remain open.
