ARBISCOUT — COMPLETE TEST VERSION
================================
1. Open Terminal in this folder.
2. Install: python3 -m pip install -r requirements.txt
3. Run the 20-item fictional demo:
   python3 run_test.py --demo --as-of 2026-11-07 --output fresh_demo --open
4. Or open DEMO_OUTPUT/index.html (already generated by tested GitHub CI).
5. To use your saved Best Buy HTML, see TEST_VERSION.md.
6. Live Best Buy scrape (works any day; uses installed Chrome, waits for prices
   to load, saves each loaded page, and does not open individual product pages):
   ./run_live.command
   It asks for a deals URL (press Return for Black Friday), then asks for a
   folder of saved eBay sold pages (Return to skip), then opens the report.
   You can also pass the URL directly:
   ./run_live.command "https://www.bestbuy.com/black-friday"

   For eBay sold evidence: open each "eBay sold" link, save the completed-listing
   page into one folder (any filename works; the app matches each page to its
   product by the eBay search query), and rerun with that folder. The report then
   shows sold low / high / mean / median, the typical middle-50% range, and
   whether Best Buy is below the eBay sold low or median. Live eBay sold-search
   scraping is not enabled because eBay's robots.txt disallows automated /sch/
   access.
   Helper that opens each eBay sold page for you to save:
   ./open_ebay_sold.command

   Live capture console (recommended): after one ./run_live.command scrape,
   run ./watch_ebay.command. It opens a local console with the same sorting and
   filtering as the Best Buy dashboard plus eBay sold columns. Click "Open next
   waiting eBay page", save the page (any filename works), and the row updates
   automatically with sold low/high/mean/median, typical range, and whether Best
   Buy is below the eBay low or median. It watches both ebay_saved/ and
   ~/Downloads, so a normal browser save is detected even if you don't change
   the save location. The console only reads files you save; it never fetches
   eBay itself. You can also click eBay sold links from the original Best Buy
   dashboard; saved pages are matched by their eBay search query.

7. API sources (Meh / Woot / Kroger): copy .env.example to .env and fill in
   your own keys, then:
   ./run_api.command meh
   ./run_api.command woot
   ./run_api.command kroger
   Each writes its own <source>_live/retailer/products.json.

8. Unified catalog (Best Buy + any API sources): ./run_catalog.command
   It merges whatever source folders exist, opens a local catalog, and lets you
   filter by source (e.g. just Woot, everything except Woot) and category, then
   sort by % off, dollar savings, current price or name. Set Top N (default 20)
   and click "Build top N selection". The selection is written to
   catalog/selected/ and the command to capture eBay evidence is shown:
   ./watch_ebay.command ebay_saved --output catalog/selected --keep-selection

   You can also hand-pick individual deals: click Save on any row, use the
   "Woot only" / "Except Woot" quick filters, tick "Saved only" to browse your
   saved list, and click "Build eBay run from saved" to send exactly those items
   to the eBay capture step. The saved list persists in catalog/saved.json while
   the catalog server is running and across restarts.

   If you downloaded a selected.json from the static catalog instead:
   ./run_selected.command selected.json

IMPORTANT: Displayed eBay sold prices are provisional, not independently
verified actual-paid historical sale prices. Gaps are gross; fees, shipping
and net margin are excluded. Live automated eBay sold-search is disabled
because eBay's robots.txt disallows /sch/ for automated agents. Historical
prototypes are retained in HISTORICAL_SOURCE_BANK.
